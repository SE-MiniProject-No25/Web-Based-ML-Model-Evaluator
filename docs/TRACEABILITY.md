# Requirement-to-Code Traceability
## Web-Based ML Model Evaluator

From a backlog item to the requirement it meets, the pull request that built it, the files that implement it, and the tests and Test Plan cases that check it:

**Backlog item → requirements (SRS) → pull request → source files → tests → Test Plan cases**

Each row can be followed in either direction. The other directions are in:

| From | To | Where |
|---|---|---|
| A requirement | the backlog items and test cases that cover it | [Product Backlog §2](../planning/Product_Backlog.md#2-requirement-coverage) |
| A requirement | the test cases that verify it | [Test Plan §7](../deliverable-1/02_Test_Plan.md#7-requirements-traceability-matrix) |
| A test case | the automated tests that run it | [Test Plan §9](../deliverable-1/02_Test_Plan.md#9-automated-test-mapping), kept true by `backend/tests/test_traceability.py` |
| A test case | its result and the defects it found | [Test Plan §10](../deliverable-1/02_Test_Plan.md#10-test-execution-record) |
| A change to a test case | the reason for it | [Deviation Log §2a](Deviation_Log.md#2a-testing-deviations-t) |

Paths are relative to the repository root. The source and test files listed are the ones each pull request changed the most and that still exist on `main`; a pull request usually changes more. Several stories share one pull request where the work was done together. The interface stories (US-12 to US-18) were built before the frontend had tests of its own; their tests are the component tests added by TEST-01 ([#92](https://github.com/SE-MiniProject-No25/Web-Based-ML-Model-Evaluator/pull/92)) and the browser tests added by TEST-07 ([#93](https://github.com/SE-MiniProject-No25/Web-Based-ML-Model-Evaluator/pull/93)).

## Where the code lives

Every feature goes through the layers of the [Architecture document](../deliverable-1/03_Architecture_and_Design.md): **web interface → API controller → validation → evaluation → metrics and results → temporary storage**. `backend/tests/test_architecture.py` fails the build if a layer imports one it should not (NFR-09).

| Architecture component | Code |
|---|---|
| Web interface | `frontend/src/` |
| API controller | `backend/app/api/` |
| Input validation | `backend/app/validation/` |
| Evaluation service | `backend/app/evaluation/` |
| Metrics service | `backend/app/metrics/` |
| Result service | `backend/app/results/` |
| Temporary storage | `backend/app/storage/` |
| Security and policy | `backend/app/security/`, `backend/app/config.py` |

## Requirements verified without a test of their own

**NFR-09** (modular architecture) is verified by the architecture review the [Test Plan](../deliverable-1/02_Test_Plan.md#7-requirements-traceability-matrix) names. [EN-04](https://github.com/SE-MiniProject-No25/Web-Based-ML-Model-Evaluator/pull/33) makes that review concrete: `backend/tests/test_architecture.py` parses every module and fails the build if a component imports one the architecture does not allow. **NFR-01** (usability) is verified by the usability test (TC-21), not by an automated test.
