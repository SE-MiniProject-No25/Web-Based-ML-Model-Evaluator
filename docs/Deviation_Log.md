# Deviation Log
## Web-Based ML Model Evaluator

Every place where what was built, or how it was built, differs from the plan in the Deliverable 1 documents ([SRS](../deliverable-1/01_SRS.md), [Architecture and Design](../deliverable-1/03_Architecture_and_Design.md), [Test Plan](../deliverable-1/02_Test_Plan.md)) and the [Product Backlog](../planning/Product_Backlog.md) and [Sprint Plan](../planning/Sprint_Plan.md). Each entry says what the plan said, what was built, why, what it affects, and where the change happened. Each affected document links back to its entries here.

Design deviations (D) change *what the system does or how it is built*; process deviations (P) change *how the team worked*; testing deviations (T, section 2a) change *how the product was tested*. Nothing here removes a requirement: every FR, NFR and SEC requirement is still met (see the [System Validation Report](System_Validation_Report.md)).

## 3. One-page summary for the demo

**What changed in the design (and why it is allowed):**
- **Same requirements, same API.** The three endpoints, their fields and the 13 error codes of SAD §10–11 are unchanged. Three extra codes cover errors outside the workflow (unknown URL, wrong method, unexpected crash), so every error has one format (D-04).
- **Models are never opened in the server.** They are opened in a child process, both to check them (before the `202`) and to evaluate them, with time and memory limits on Linux and Windows. It is process isolation, not a container, and that is stated as a limitation (D-02, D-03, D-07).
- **Authentication is an optional API key** (the SRS left the mechanism open) (D-05).
- **Results live in memory** for the session, as FR-18 asks; download is JSON (D-08, D-09).
- **Part-3 testing changed four things:**
  - Retention runs on a timer and never deletes files in use (D-06).
  - Text class labels work (D-10).
  - Common CSV variations are handled or refused clearly (D-12, D-13).
  - Acknowledgement is about 0.2 s instead of 1.7 s (D-11).

**What changed in the testing (T-01 to T-12):**
- The Test Plan grew from 22 to 25 cases and every case was reworded to the application as built, with a Revision History and a result recorded for each case (Test Plan section 10). No case was removed.
- TC-12, TC-15, TC-17, TC-18 and TC-19 changed because the product changed (download button, Windows memory limit, authentication, retention timer, acknowledgement pace).
- Coverage is measured and enforced in CI, on Windows and Linux, with frontend and browser tests added.

**What changed in the process:**
- The sprints overran. Sprint 1 (19–23 Oct) was completed on 28 Oct, Sprint 2 (26–30 Oct) on 10 Nov and Sprint 3 (1–6 Nov) at the freeze on 11 Nov. A **Sprint 3** finished the spill-over and did the Part-3 testing (P-01, P-02).
- Akash's backlog items were tracked under test-story issue numbers (P-03).
- Most pull requests were checked and merged by the team lead without a formal GitHub review. Three commits went straight to `main` after the freeze (P-05).
- The interface stories were not all raised by their assignee: the team lead connected the first interface to the real API (#45), and three of Akshath's own pull requests were merged by him (P-07).
